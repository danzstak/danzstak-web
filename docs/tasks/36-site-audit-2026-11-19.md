# 36 — Site audit, 2026-11-19: every page, every button, one web app

The owner asked Claude (the planning chat) to go through every page and every button, write down each bug, and plan the fixes. Claude Code builds the fixes. One PR per group (A, B, C…), in the order below.

**How the audit was done.** Every page was loaded at 390×844 (phone, touch), signed in with a mocked API, in Playwright Chromium. That covers 32 screens: Mix, HQ, Events, Tribes, Friends, Photos, Videos, Saved, Settings, Menu, Profile, SYNC, the SYNC app, EPK, Booking, Tour Manager, Bazaar, Product, Store, Shop manager, Record Stores, Event, Moving Day, Support, Privacy, Terms, Trusted contacts, Answer, Booking reply, Booking opt-out, and the signed-out landing page. Each screen was screenshotted, checked for script errors, overflow, broken images, native form controls and fonts, and then **every visible button (up to 45 per page) was clicked on a fresh load**.

Items marked **(owner)** were found by the owner on his phone. Items marked **(audit)** were reproduced here. Items marked **(check)** could not be proven in the sandbox and must be checked on the live PWA first.

**Rule for Claude Code:** for each item, reproduce it, fix the root cause, add a test (static or a `browser-checks/` file) that would have caught it, and screenshot at 360 and 390px before and after.

## A. Broken: things that don't work (fix first)

A1. **(owner) A posted video doesn't appear in Dailies or The Roll.** The owner posted a video as Eroticon and found it in neither place.
- Root cause from the code: Dailies and The Roll are **opt-in checkboxes** in the Mix composer (`#shareToStory`, `#shareToReels` in `feed.html`). The server only marks a post as a Roll video when the client sends `reel: true` (`infrastructure/auth-api/index.mjs`, `const reel = mediaType === "video" && data.reel === true`).
- The other composers never send it: the profile composer, the Tribe composer and the event composer upload with `purpose: "post"` in `assets/feed-enhancements.js`.
- The owner rule (2026-11-18) is that every photo or video post goes into Dailies for 24 hours, and every video also goes into The Roll for good, **automatically, from any composer**.
- Fix it **on the server** when a post is created with media: a video sets `reel` and a Dailies entry, a photo sets a Dailies entry. Remove both checkboxes from the composer.
- Backfill: the owner's session runs a one-off script so existing video posts (including Eroticon's) get `reel: true`.
- Test: post a video from the profile composer, and it shows in the `/stories` reels and Dailies payloads.

A2. **(owner) Tapping the Dailies tile opens the phone's photo picker.**
- Your own tile opens your Dailies in the full-screen viewer, or the composer when you have none. It never opens a file picker.
- A friend's tile opens their Dailies.
- Rule (owner 2026-11-19): **the only profile picture that opens the image picker is the big profile picture on your own profile page**, which edits that picture. **Every other profile picture anywhere opens that member's profile.**
- Test: no `filechooser` event fires from any tile or avatar except the owner's own big profile picture.

A3. **(owner) The Roll goes silent when it opens full screen.** Sound was on in the Mix carousel, but the full-screen Roll opened muted.
- The sound choice must carry over both ways: inline → full screen → back.
- Use one shared preference (e.g. `danzstak_roll_sound`), only ever set by a tap, so the autoplay rules still hold.
- Also from the same screenshot: the video doesn't fill the width (there's a strip at the lower right) and there's a grey bar above "The Roll" header. Make it fill edge to edge.

A4. **(audit) The Saved page is blank.** It crashes with `Cannot access 'volatilePostPreferences' before initialization` (a `let`/`const` used before it is declared, in the feed scripts) on `feed.html#saved`. Every tap on that page throws the same error.

A5. **(audit) Record Stores crashes.**
- `Cannot read properties of undefined (reading 'length')` on load, and "Loading your store list…" never finishes.
- "Find record stores" does nothing.
- Guard the missing workspace fields, and show an empty state instead of a spinner.

A6. **(audit) The shop manager (`store.html?manage=1`) shows a raw JavaScript error to the member** ("Cannot read properties of undefined (reading 'length')").
- The Shop name and About fields are empty even though the shop has a name.
- "Save shop" with an empty name does nothing and says nothing.
- **Never show a raw error to members anywhere**: add one shared friendly-error helper and a test that greps page text for "Cannot read properties" / "undefined".

A7. **(audit) Booking: "Example" and "Find clubs" (with an empty search) do nothing.** Example should fill the tour sentence. An empty Find clubs should say what to type.
- (check) The club map loads Leaflet from unpkg.com. It was blocked here, so every map button was unclickable. Confirm it loads on the live PWA, and **ship Leaflet locally** (`assets/vendor/`) so the map doesn't depend on a third-party CDN.

A8. **(audit) A Tribe you're the Elder of shows "Join".** The Tribes list showed "Elder · 12 members" with an orange **Join** button.
- Members and Elders see "Joined" or ⋯, never Join.
- The list also opens on **Discover** even when you have Tribes. Open on Your Tribes.

A9. **(audit) The composer avatar in Mix does nothing when tapped.** Per A2 it opens your profile.

A10. **(audit) The Photos page (Menu → Photos) shows other people's photos as text cards.** "Flyer for Friday" came from Tour Friend.
- It must show only **your** photos, in the 3-column grid with albums (5a2).
- Same for Menu → Videos.

A11. **(owner) The "+ bio" button opens Edit profile.**
- It should open the member's **long bio** editor, so they can write or extend the long bio straight away.
- The button is **only for the account holder**: never shown on someone else's profile.
- Test: on your own profile, + bio opens the long-bio editor. On another member's profile, the button isn't in the page.

A12. **(owner) Remove the "@username" line under the profile name** ("@sfscoop … that is useless"; "most users already know the @ and # symbols").
- In its place, show the **friends row**: small overlapping photos of that member's friends, plus "N friends" (spec 5a3).
- Tapping a friend's small photo opens **that friend's profile at their posts**.
- Tapping the count opens the Friends screen.
- @username stays only where it's needed to find someone: search results and the Edit profile field.
- Don't add explainer text about @ or # anywhere.

A13. **(owner) Shop storefront on the profile.** The empty white space to the right of the big profile picture (between the avatar and the right edge, under the cover) becomes a **small storefront**, so the shop is a storefront and not a little shop button.
- It shows the member's shop name and a preview image of one item, rotating through active items, with the price.
- Tapping it opens the profile's Shop tab at that item.
- Only shown when the member has a published shop with at least one active item; otherwise the space stays as it is.
- Visible to everyone who can see the profile.
- Phone first: it fits beside the avatar at 320px with no overlap and keeps the 44px touch target.
- Once the storefront is there, remove the small shop icon button from the action row.

## B. One web app: things that look like different sites

B1. **Five different top bars.**
- Mix, HQ, Events, Tribes, Friends and Settings use logo + search box + bell + SYNC.
- Bazaar, EPK, Booking, Record Stores and Moving Day use logo + search icon + bell + SYNC.
- Product and Event use logo + white boxy "Bazaar / My Shop" or "Events / SYNC" buttons.
- Tour Manager uses "← Back to venue map" + a small logo.
- Support uses a logo + "Back to Settings" link.
- Profile uses "← name + search".
- SYNC has its own header. That's fine, SYNC is meant to feel like its own app.
- **Fix:** one shared app bar component on every DanzStak page except SYNC and the full-screen viewers: logo, search box, bell, SYNC. Pages that need Back put ← in the same bar.

B2. **Bottom tabs differ.**
- The tab bar in `feed.html` and the one on the other pages have different widths and icon spacing: icons sit at 35/99/163px on Mix but 22/86/150px on Bazaar, EPK and SYNC.
- The highlighted tab is wrong in several places: HQ, Events, Tribes, Friends and Photos don't light up their tab; Profile, Tribes, Photos and Saved light up **Menu**; Moving Day lights up **Bazaar**.
- Tour Manager, Support, Trusted contacts, Privacy and Terms have **no bottom tabs**.
- **Fix:** one tab bar component, one rule for which tab is lit (a page → tab map in one file), and the bar on every signed-in page.

B3. **Fonts differ by page.** DanzStak Sans on Mix and Profile, Inter on Tour Manager and Support, Arial on Landing, Privacy, Terms and Booking reply, Archivo on EPK and Trusted contacts, Segoe UI/system on SYNC. Use the design-system fonts everywhere except artist genre looks (EPK, public pages).

B4. **Two different post designs.**
- Mix posts have an icon row with counts (like, dislike, comment, share, save), relative dates ("2D") and the author's photo.
- Profile posts have emoji text buttons ("👍 Like 💬 Comment ↗ Share"), a "0 comments" line and US dates ("11/16/2026, 9:30:00 PM").
- **Fix:** one post component (Mix's) on Mix, Profile, Tribes and Saved.

B5. **Your own avatar shows "N" instead of your photo** on your own posts in Mix and in the profile composer, even though the profile has a picture. Use the member's photo everywhere and the initial only when there's none.

B6. **Primary buttons come in three styles**: orange (Mix, Profile, Tribes), black (Events "Add Event", Booking "Plan my run" / "Find clubs", Shop "Save shop", Support, Settings "Save Settings") and grey boxes (Settings "Manage" / "View" / "Review" / "Logout", Friends "Invite a friend"). Use one primary (orange), one secondary and one icon button from 16-C everywhere.

B7. **Native browser controls still show**:
- the Events file picker, `mm/dd/yyyy` date/time fields and select;
- Settings checkboxes and the language select;
- EPK, Booking (8 selects, 2 date fields), Shop and Support selects;
- Tour Manager date fields;
- Moving Day file input;
- the oversized blue "Require legal names" checkbox on Events.

Give them one styled set: switch, select, date and file picker.

B8. **Screens are panels on panels.**
- Tour Manager looks like a 1997 form: blue numbers, plain text links, a raw number box for credits.
- Support is a card inside a page.
- Settings has two titles ("Settings" + "Settings and privacy").
- HQ is grey boxes plus pills and a lot of empty space.

Apply the fluid-page rules from CLAUDE.md (hairline dividers, no boxes in boxes).

B9. **The Landing page (signed out) is generic and off-brand.**
- Purple headings and accent, and "Social Networking / Creator Discovery / Industry Connections" cards that read like a template.
- Blue footer links.
- A grey "Sign Up" button that looks broken: it's disabled until the terms box is ticked, with no hint.

Use DanzStak orange, the music-first message (EPK and booking first, then Mix and SYNC), a Sign Up that explains it needs the terms box, and the footer in brand colors.

B10. **Bazaar product images sit in white boxes** (letterboxed with white bars). Show them as square images filling the tile, with a dark backdrop for odd shapes.
- Bazaar also has **two searches** (header icon + body field). Keep one (T2g).

### New or reconfirmed bugs (fix in this order)

E1. **Mix: tapping the Comment icon does nothing.**
- Where: `feed.html` around line 1705, `feed.addEventListener("click", …)` tests `event.target.classList.contains("commentBtn")`.
- Since the icon system, a tap lands on `span.reaction-icon` inside the button, so only a tap on the button's outer edge opens comments.
- Reproduced: a tap at the icon centre leaves the comments closed; a tap 4px from the corner opens them.
- Fix: `const button = event.target.closest(".commentBtn, .likeBtn")` and branch on that. Grep the rest of the site for `event.target.classList.contains(` on buttons that now hold icons.
- Test: a browser check taps the centre of Comment and expects the comment box open and focused.

E2. **Trusted contacts: "ADD CONTACT" shows a raw error to the member**: "Cannot read properties of undefined (reading 'join')". Guard the missing field. Covered by the friendly-error helper in A6.

E3. **Shop manager (`store.html?manage=1`) raw error, reconfirmed**: now "reading 'name'". **Every "My Shop" / "Open my shop" link lands there** (Bazaar, Product, Store, Profile), so testers hit it from four places (A6).

E4. **Forms that say nothing when they can't submit.** *(Re-checked: Events and Support use the browser's own `required` validation, which shows its "Please fill out this field" bubble on Android and iPhone; the crawler can't see that bubble. Not a bug there. Fixed for Save shop, which now says "Give your shop a name first.")*
- Events "Add Event" with an empty form: nothing happens.
- Support "Send to DanzStak Support" with an empty form: nothing happens.
- Shop "Save shop" with an empty name: nothing happens (A6).
- Fix: one shared inline message under the first missing field ("Add a title", "Pick a topic"), focus that field, and keep the button enabled.

E5. **Dailies tile still opens the photo picker** (A2), on Mix and on the signed-out `index.html` view.

E6. **Saved page still crashes** (A4: `volatilePostPreferences` used before it is declared). **Record Stores still crashes** (A5: "reading 'length'"), including when it is opened from Music HQ → Record shops.
